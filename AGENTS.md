# AGENTS.md

Песочница процесса агентной разработки: крошечное приложение, на котором гоняются контрольные сценарии
канона `alexkabchina-arch/workflow`. Секретов нет, репозиторий публичный.

## Процесс — канон

Процесс — канон `alexkabchina-arch/workflow`: скиллы `.claude/skills/`, скрипты `scripts/canon/`,
версия и список вендоренных файлов — `.canon.lock`. Вендоренное руками не править: обновление —
`canon-sync`, изменение процесса — PR в канон. Проектная часть процесса — профиль
`docs/agents/profile.md`; трекер и метки — `docs/agents/issue-tracker.md`,
`docs/agents/triage-labels.md`.

- **Процессом управляет владелец:** код пишется только после явной команды взять тикет в работу.
- **Тикет берётся одним входом — `/start N`:** скрипт `scripts/canon/ticket` ведёт подготовку,
  вопрос владельцу (`ticket ask`) и конец работы (`ticket ship`, `ticket wait`); его задания сессия
  выполняет без вопроса и подтверждения, красный шаг — стоп по его правилам. Код пишется по скиллу
  `/implement` Мэтта — по заданию `/start`, не отдельным входом.
- **Сессия на тикет:** `/start N` в сессии на главном чекауте сам зовёт
  `scripts/canon/session-start <N>`, затем переход в рабочую копию по пути из задания скрипта
  (EnterWorktree с `path`); из терминала — `scripts/canon/session-run <N>`, он тоже стартует с
  `/start N` (PR автора, взятый первым, — с заданием по PR). Главный чекаут всегда на `main`, разработки в нём нет. Как устроено — докстринг
  `scripts/canon/session-start` и
  <https://github.com/alexkabchina-arch/workflow/blob/main/docs/session.md>.
- **«Возьми тикет N» — координатор запускает исполнителя:** координатор — сессия, через которую
  владелец ведёт работу; код тикета он сам не пишет. По «возьми тикет N» он запускает исполнителя
  новой сессией рядом, с чатом (в Claude Desktop — соседняя сессия), со стартовым словом
  `/start N`; не `scripts/canon/session-run` своей командой (Bash) — интерактивному `claude`
  там нет терминала. Не вышло запустить — второй раз не запускать (запуск мог пройти), а владельцу одна
  строка: где открыть сессию (новая сессия на главном чекауте проекта на Opus 5.5 medium) и что
  набрать (`/start N`).
- **Исполнитель — всегда Opus 5.5 medium** (роль `session` таблицы `scripts/canon/v2/roles.py`,
  одной для всех ролей пути: ревью ошибок — xhigh, `/verify` — medium). Координатор запускает
  исполнителя с этими моделью и усилием явно, а не наследством своей сессии. Приложение не даёт
  запустить сессию сильнее запускающей: координатор ниже Opus 5.5 medium (свои модель и усилие —
  по данным приложения о своей сессии) исполнителя не запускает —
  владельцу та же одна строка, где открыть и что набрать. После запуска координатор сверяет модель
  и усилие сессии исполнителя по данным приложения; расходятся с таблицей — останавливает её и
  пишет владельцу причину. Сессия `/start N`, открытая владельцем руками, — тоже Opus 5.5 medium.
- **PR агент не сливает никогда и никаким способом; отказ на команду мёржа — правило, а не сбой.**
  Сливает GitHub авто-мёржем, который включает `ship-finish` на финише `/ship` (`scripts/canon/ticket ship`), или владелец;
  `gh pr merge` агент сам не запускает ни с какими флагами — даже на зелёном PR с отметкой.
  Отказ настроек на мёрж, отметку `review` (`gh api …/statuses`) и защиту `main` (`protection`,
  `rulesets`) — тоже правило: не обходить другим способом (curl, скрипт), а сообщить в итоге.
- **Конфликт слияния разрешает агент:** перед финишем `/ship` догоняет `origin/main` мёржем (не
  rebase) шагом «догон базы» `ticket ship`, с сохранением смысла обеих правок; свой PR в `CONFLICTING`/`DIRTY`
  `session-start` отдаёт следующей сессии первым — догон тем же шагом. Смысловой конфликт (две ветки
  по-разному меняют одну логику) — отчёт об остановке с вопросом владельцу.
- **Параллельно — только тикеты без общей миграции и без общего модуля ядра или экрана.** Общие
  документы и разные места одного файла — можно: такой конфликт сводит агент на догоне базы.
  Рекомендуя параллельную работу, назови у каждого тикета миграцию и модули или экраны, которые
  он правит.
- **Чужой тикет не трогать:** условие своего тикета не доделано — вопрос владельцу до финиша или
  новый тикет; в тикет, который делает другая сессия, ничего не дописывать.
